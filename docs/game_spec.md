# JigsawPuzzle ゲーム仕様書

## 1. 概要
- GitHub Pagesで公開する、PC・タブレット対応のブラウザ用ジグソーパズル。
- HTML / CSS / JavaScriptで構築し、バックエンドを必要としない。
- パズルの画像は、開発者が用意した画像（設定JSONに登録）と、ユーザーが選択した画像（ブラウザ内で処理・保存）の両方に対応する（3章）。
- ユーザーが選択した画像はサーバーへアップロードしない。
- 最終目標は70ピース（10列×7行）とする。初期開発・検証は引き続き3列×3行の9ピースで実施する。

## 2. 画面構成
### 2.1 作業エリアと土台
- 画面のうち操作パネル以外の領域全体を「作業エリア」とする。作業エリアの縦横比は表示領域に合わせ、使われない余白を作らない。
- 土台は作業エリアの中央に置く。土台の長辺は論理座標で750とする。
- 表示倍率は、総ピース数ぶんの置き場（凹凸を含めた1ピース分＋ピース間の間隔の区画）を土台の周囲に確保できる範囲で、土台が最も大きくなる値とする。
  - 倍率は、パズル読み込み時と画面サイズ変更時に計算し直す。プレイ中にピースを固定しても倍率は変えない。
- 未配置ピースは土台の外にランダムに散らばった状態で開始する。重ならないように配置し、土台を隠さない（4章）。
- 70ピースでは置き場が不足し、土台が小さくなりすぎる可能性がある。未配置ピースの縮小表示、作業エリアの拡大・移動（パン）、ピース置き場などを後の設計段階で検討する（13章）。

### 2.2 座標系
- ピースの位置・土台の位置は、**土台の左上を原点とする論理座標**で管理する。土台は (0, 0) から (土台幅, 土台高さ) の範囲にある。
- 作業エリアは「画面に見えている範囲」として論理座標で表し、土台の外側（負の座標を含む）に広がる。
- ピースの位置はピース本体（凹凸を除いたマス）の左上で表す。
- 論理座標は画面サイズ・操作パネルの位置・表示倍率に依存しない。結合・吸着の判定やセーブデータもこの座標を用いる。

### 2.3 操作パネル
- 操作は1つの操作パネルにまとめる。
  - **横長の画面（PC・タブレット横向き）：** 画面右側に縦長のパネルを置く。項目が増えた場合はパネル内でスクロールする。
  - **タブレット縦向き：** 画面上部に置く。
  - **狭い画面（幅600px以下、または高さ500px以下）：** 上部（横長の場合は右側）にコンパクトに置く。
- パネルに置くもの（上から順）：
  1. 完成図サムネイル
  2. パズル名・完成数
  3. 画像切り替え用リストボックスと「がぞうを えらぶ」ボタン（3.3）
  4. セーブ・ロード（画像ごとに3スロット）
  5. アシストON/OFF
  6. 音量調整・ミュート（ON／OFFボタン「おと ON」「おと OFF」と、音量スライダー「おとの おおきさ」。6章）
  7. 最初から遊ぶ（ボタンの表示名は「さいしょから」）
- 完成図サムネイルは縦横比を維持し、最大サイズは次のとおりとする。
  - 横長の画面：176px四方
  - タブレット縦向き：144px四方
  - 狭い画面：72px四方
- サムネイルをクリック・タップすると、背景を暗くして完成図を画面全体に大きく表示する（縦横比を維持し画面内に収める）。
  - 拡大表示中にもう一度クリック・タップするか、Escキーを押すと元の画面に戻る。
  - 拡大表示中は背後の画面を操作できない。

### 2.4 表示内容
- 画像切り替え用リストボックス、完成数・総ピース数、セーブ・ロード操作を用意する。
- 完成数は**土台に固定されたピース数**とする（例：「3 / 9」）。ピースを固定するたびに更新する。
- 土台に固定されたピースは影をなくし、土台にはまった平らな見た目で表示する。
- 土台は、外周を四角い枠、内部の境界線をピースと同じジグソーの凹凸形状で表示する。
  - 境界線はピースの形状データ（同じ辺データ）から描き、土台の各マスの枠と実際のピースの形を完全に一致させる。
  - 隣り合うマスが共有する境界線は1回だけ描き、二重描画で線が太くならないようにする。
  - 列数・行数で一般化し、3×3以外（10×7など）でも同じ方法で描く。
- アシストOFFのとき、土台は枠線（外周の枠と凹凸の境界線）のみを表示する。
- **アシスト表示**：土台に完成画像を非常に薄く表示する機能を設ける。
  - 完成画像は土台の下地と境界線の間に重ね、ONでも境界線が見えるようにする。
  - アシストON/OFFボタンを設置する。初期値はOFF。
  - ONのときの不透明度は10〜15%程度を目安とする。
  - アシスト表示は見た目の補助であり、結合・吸着の判定には影響しない。
- 効果音・音楽の音量調整とミュート切り替えの操作を用意する（6章）。
- 小さな画面ではレイアウトを調整し、作業エリアを優先して広く表示する。スクロールや操作ボタンとドラッグ操作が干渉しないようにする。
- 画面が狭い場合は、表示倍率を下げて土台と置き場を画面内に収める（2.1）。
- 配色はライト配色のみとする。端末の外観設定（ダークモード）やブラウザの自動ダーク化に関係なく、同じ配色で表示する。
- 対象は6歳児のため、画面に表示する文言（ボタン名・確認メッセージなど）はできるだけひらがなにする。既存の表示文言の見直しは、変更の依頼があったときに行う。
- 土台・ピースの拡大縮小や作業エリア移動は、操作方法を設計して後の段階で実装する。タブレットのピンチ操作等は初期9ピース版の必須要件にしない。

## 3. 画像と難易度
### 3.1 共通
- パズルの画像には「開発者が用意した画像」と「ユーザーが選択した画像」の2種類がある。
- 画像は「画像の種類（開発者／ユーザー）＋画像ID」で識別する。セーブデータもこの組み合わせで画像を参照し、どちらの種類の画像を参照しているか判別できるようにする。
- 画像IDは種類ごとに一意で、一度決めたら変更しないことを原則とする。セーブデータとの対応に利用する。
- ピース数は画像ごとに固定し、列数×行数で定義する。
- まずは9ピース（3列×3行）で検証する。その後、画像ごとに別のピース数を設定できるようにし、最終的に70ピース（10列×7行）でプレイできるようにする。
- 画像が見つからない場合（ファイルがない、保存データが削除された等）はエラーを表示し、他の画像のプレイは継続可能とする。
- 画像切り替え用リストボックスでは、両方の種類の画像を選べるようにする（並べ方・区別の表示方法は13章）。

### 3.2 開発者が用意した画像
- 開発者が `images/` に配置し、`data/puzzles.json` にID、表示名、画像パス、列数、行数を登録する。
- 開発・テスト用の画像は `images/sample.jpg` を使用する。

### 3.3 ユーザーが選択した画像
- ユーザーが端末から選択した画像を、ブラウザ内だけで処理してパズルにする。サーバーへはアップロードしない。
- 選択した画像は、将来的にブラウザ内のIndexedDBへ保存し、次回以降も選べるようにする。
- 画像IDはブラウザ内で発行し、保存後は変更しない。
  - 手順7では、選ぶたびに `user-` で始まるIDを発行する（開発者の画像のIDと重ならないようにする）。凹凸の形はこのIDから決まる。
- **画像の選択（手順7で実装）：**
  - 操作パネルの「画像切り替え」の位置に、リストボックスと「がぞうを えらぶ」ボタンを置く。ボタンで端末のファイル選択画面を開く（標準の `<input type="file">`。iPadでは写真ライブラリ・ファイルなどから選べる）。選択画面でキャンセルした場合は何も変えない。
  - 受け付ける形式は JPEG・PNG・WebP（`accept="image/jpeg,image/png,image/webp"`）。実際に使えるかは、ブラウザで画像として読み込めるかで判断する。iPadの写真（HEIC）は端末側でJPEGに変換されることを想定するが、accept 属性だけでは保証されないため、読み込めない場合はエラーを表示する。
  - 元画像のファイルサイズは50MB以下。短辺が200px未満の画像は使わない。
  - 長辺÷短辺が2を超える画像は、中央を切り取って2:1に収める（縦長・横長とも）。2:1以内なら切り取らない。
  - 長辺が2048pxを超える場合は2048pxに縮小し、JPEGに変換して使う。透明部分は白にする。写真の向き（縦向きで撮った写真）はブラウザの読み込み時の向きに従う。
  - ピース数は3列×3行の9ピースで固定する（ユーザーが選べる機能は後の工程）。
  - 表示名は「えらんだ がぞう」とする。元のファイル名は表示しない。
  - リストボックスでは、開発者の画像（サンプル）と、さいごに選んだユーザーの画像1枚を切り替えられる。新しく選ぶと前の画像と入れ替わる。画像は保存しないため、再読み込みすると消える。
  - 画像は端末内（ブラウザのメモリ上）だけで処理し、外部へ送信しない。使わなくなった画像のデータ（Object URL）は、切り替えが成功した後に解放する。
- **エラー：** 50MBを超える・小さすぎる・読み込めない画像は、今のパズルをそのまま残し、ひらがなのメッセージ（例「この がぞうは つかえません。ちがう がぞうを えらんでね。」）を表示する。
- **画像を変えるとき：**
  - 固定済みのピースが1つでもある場合は、変える前に「いまの パズルを やめて、ちがう がぞうで あそぶ？」と確認する（`confirm()`）。キャンセルなら今のパズルを残す。固定済みのピースがなければ確認しない。
  - 画像の読み込みが成功してから入れ替える。入れ替え時は、ドラッグ・拡大表示・完成演出を終了し、鳴っている効果音を止め、ピースの位置・結合・固定・完成状態・表示順・完成数を初期化する。音量・ミュートの設定は変えない。
  - 短時間に何度も選んだ場合は、さいごに選んだ画像だけを反映する。
- 画像の保存（IndexedDB）は後の開発手順で実装する（11章）。詳細は13章の未確定事項を実装前に確認する。

## 4. ピース生成と操作
- ピースは一般的なジグソーパズルの凹凸形状とする。隣接する辺は互いにかみ合い、外周辺は直線にする。
- 凹凸形状は画像IDから決定し、同じ画像では毎回同じ形になるようにする（セーブ・ロード後も同じ形を再現できる）。
- 元画像の対応部分を各ピースの形状で切り抜いて表示する。
- PCはマウス、タブレットはタッチでドラッグして移動する。
- ピースの回転機能は実装しない。
- 結合済みのピースは一つのグループとして移動する。複数グループの結合にも対応する。
- 土台外で結合したピースも移動できる。

### 4.1 結合・吸着（スナップ判定）
- 正しく隣接するピース同士が、本来の相対位置から一定距離以内に近づいた場合は結合する。
- 土台上の正しい位置に近づいたグループは吸着・固定する。固定されたピースは誤操作で動かない。
- 固定済みピースの隣に正しいピースを近づけた場合も、土台に吸着して固定する。
- スナップ判定距離は、**ピースの短辺の約25%**を初期目安とし、少し広めにする。値は動作確認しながら調整する。
- 判定距離は作業エリアの論理座標で扱い、画面の縮小率に左右されないようにする。
- 結合・吸着の判定は見た目だけでなく、ピースIDと本来の相対位置を用いる。正しいピース・正しい位置関係の場合のみ結合・吸着し、誤ったピース同士は判定距離内でも結合しない。
- 結合の対象は、正しく上下左右に隣り合うピース（同じマスの隣）だけとする。斜めや離れたマスのピースは結合しない。
- ドロップ時の判定順：
  1. グループのいずれかのピースが正解位置から判定距離以内なら、グループ全体を正解位置に置いて固定する（結合より優先）。
  2. 正しく隣り合う未固定のグループと、位置関係のずれが判定距離以内なら結合する。
  3. 結合で大きくなったグループについて、新たな固定・結合がなくなるまで1・2をくり返す。
- 複数の相手と同時に結合できる場合は、ドロップしたグループを、位置関係のずれが最も小さい相手に合わせる。ほかの相手は、合わせた後のずれが判定距離以内に残る場合だけ結合し、相手グループ全体を結合済みのグループに合わせて動かす。判定距離を超える無理な結合はしない。
- 結合・固定のときは、グループ内のピースの正しい位置関係を常に保つ。固定済みのピースは結合の相手にせず、動かさない。
- 結合したグループが作業エリアからはみ出す場合は、グループ全体を範囲内に戻す。

### 4.2 配置と表示順
- 未配置ピースの初期配置は作業エリア内で行い、ピース同士が重ならないように配置する。重なりの判定には凹凸を含めたピースの範囲を用いる。
- 未配置ピースが他のピースに完全に重なって見えなくならないようにする（ただし、下記のとおり空き場所がない場合は無理に移動しない）。
- 表示順は各ピースの表示順の値（z）で管理する。zはセーブ対象とし、ロード時に重なり順を復元する（7章）。
- ドラッグ中は、対象のピースまたは結合グループを最前面に表示する。
- ドロップ後も、最後に動かしたピースまたはグループを最前面のままにする。結合した場合は、結合後のグループ全体を最前面にする（グループ内の重なり順は保つ）。
- 土台に固定されたピースは、zに関係なく常に未配置ピースより背面に表示する。
- **ドロップ後に完全に隠れたピースの扱い（自動移動）：**
  - 判定はピース1個ずつ行う。下になった未配置ピースの中心部分（凹凸を除いたマス＝本体部分）が、上にある**1個のピース**の外接範囲（凹凸を含む）内に完全に入っている場合に「隠れている」とする。グループ全体の外接範囲では判定しない。
  - 複数のピースにまたがって隠れるケースは、現段階では自動移動の対象にしない（グループ結合の実装時に必要であれば見直す）。
  - 隠れている場合は、**下になったピース**を近くの空き場所へ自動移動する。プレイヤーが置いたピース・グループの位置は変えない。
  - 自動移動先の「空き場所」は、作業エリア内で、他のピースおよび土台に重ならない場所とする。移動量はできるだけ小さくする。
  - 空き場所が見つからない場合は、無理に移動しない。
  - 「土台に重ならない」は自動移動の移動先に関するルールである。通常のドラッグ操作で、ユーザーが意図的にピースを土台の上へ置くことは禁止しない。

### 4.3 移動範囲
- ピースや結合グループは作業エリア（画面に見えている範囲）の外に移動できない。ドラッグ中にポインタが作業エリア外に出ても、ピースは作業エリア内に留める。
- 画面サイズ変更・端末回転の後も、ピースや結合グループが操作できない位置に残らないようにする。
  - 作業エリアの外に出た未固定のピース・グループは、作業エリア内に戻す。
  - 戻した結果、他のピースや土台と重なる場合は、空いている置き場（なければ重なりが最も少ない位置）へ移す。作業エリア外に残すと操作できなくなるため、ドロップ後の扱い（4.2：空き場所がなければ移動しない）とは異なり、必ず作業エリア内に移す。
  - 作業エリア内に残っているピースは動かさない。土台に固定されたピースは動かさない。
- 画面が狭い場合の配置・ズーム仕様は検証しながら調整する。

### 4.4 ドラッグ操作
- マウスとタッチの両方で操作できる。
- 画面上で4px以上移動した時点でドラッグ開始と判定する。タップ（クリック）しただけではピースを移動しない。
- ドラッグ開始時にピースが急に移動（開始判定までの移動分だけ跳ぶ）しないようにする。開始後は指・ポインタの移動量だけ動く。グループ移動でも同じ。
- 同時に動かせるのは1ピースまたは1グループだけとする。ドラッグ中に別の指・ポインタで別のピースを動かすことはできない。
- ドラッグ中のピース・グループは拡大せず、影を濃くして持ち上げていることを示す。
- 土台に固定されたピースはドラッグできない（4.1）。
- 当たり判定はピースの形（凹凸を含む輪郭の内側）とし、凹凸の外側の透明な部分では下にあるピースを操作できるようにする。

## 5. 完成判定・演出
- 全ピースが土台の正しい位置に固定された時点で完成と判定する。
- 完成時は画面中央に大きく「できた！！！」と表示し、背景をやや暗くする（黒の不透明度40%程度）。表示中は背後の画面を操作できない。
- 「できた！！！」の表示と同時に、完成時のファンファーレを再生する（6章）。
- 最後のピースを吸着して完成したときは、ファンファーレを優先し、通常の吸着音は重ねて再生しない。
- メッセージはクリックまたはタップで閉じられる。Escキーでも閉じられる。
- 閉じた後は完成画像全体を見られる。画像切り替えやセーブ操作も可能とする。
- 完成演出（表示・ファンファーレ）は同一の完成イベントで重複して表示・再生しない。
- 「最初から遊ぶ」ボタン（表示名：「さいしょから」）を操作パネルに常に表示し、開始直後・プレイ中・完成後のいつでも使えるようにする。押した場合は確認を表示し、承認後にピースを初期状態へリセットする。
  - 確認はブラウザ標準の確認ダイアログ（`confirm()`）で行い、メッセージは「さいしょから やりなおす？」とする。キャンセルした場合は、ピースの位置・結合状態・固定状態・完成状態を一切変更しない。
  - リセットでは、ピースの位置・結合状態・固定状態・表示順を初期化し、最初に開いたときと同じ方法で新しくランダムに配置する。ピースの形・画像・正解位置は変えない。完成数を0に戻し、再びドラッグできる状態にする。
  - リセット後もボタンは表示したままにする。リセット後に再び完成した場合は、新しい完成として演出を表示する。

## 6. 効果音・音楽
- 効果音・ファンファーレには、`assets/audio/` に置いた次の音声ファイル（フリー素材）を使用する。

  | 場面 | ファイル |
  |---|---|
  | ピース同士の結合時 | `assets/audio/piece_join.mp3` |
  | 土台への吸着時 | `assets/audio/piece_snap.mp3` |
  | 全ピース完成時（ファンファーレ） | `assets/audio/puzzle_complete.mp3` |

- 完成時はファンファーレを優先し、最後のピースの吸着音は重ねて再生しない（5章）。
- **音源の配布元：** 効果音ラボ（https://soundeffect-lab.info/）。
  - ゲームの操作音として使用し、リポジトリ（GitHub・GitHub Pages）に含めて公開する。
  - クレジット表記は必須ではない。表記するかどうかは任意とする（表記する場合は画面やREADMEに「効果音ラボ」と記載する）。
  - 配布元の利用条件を守って使用する。ゲーム内で効果音として再生する以外に、音源ファイルを自由に再生・ダウンロードできる機能（音源一覧、試聴ページ、ダウンロードリンク等）は作らない。
- 常時流れるBGMは設けない。音は上の3種類の効果音だけとする。
- **鳴らす音の選び方：** ピースを1回離す（ドロップする）ごとに、次の優先順で1つだけ鳴らす。
  | ドロップの結果 | 鳴らす音 |
  |---|---|
  | 完成した | 完成音だけ（鳴っている効果音をすべて止めてから鳴らす） |
  | 土台に固定した（同じドロップで結合も起きた場合を含む） | 吸着音だけ |
  | ピース同士が結合しただけ | 結合音 |
  | どれも起きない | 鳴らさない |
- 「さいしょから」でリセットしたときは、鳴っている効果音をすべて止める。リセットでは音を鳴らさない。
- **再生方法：** Web Audio API（`AudioContext`）で再生し、`GainNode` で音量を調整する（iPad Safariでは `<audio>` 要素の音量を変更できないため）。ライブラリは使わない。
- **音量調整とミュート：**
  - 音量はすべての効果音で共通の1つとし、0〜100の整数で調整する。初期値は50。
  - ミュートは「おと ON」「おと OFF」のボタンで切り替える。ボタンには今の状態を表示する。初期値はON（ミュートしない）。
  - 音量0とミュートは別の設定として扱う。ミュート中に音量を変えてもミュートのままとし、解除したときに変更後の音量で鳴る。
  - 音量スライダーは動かしている間もすぐに反映する。スライダー操作で試し音は鳴らさない。
- **設定の保持：** 音量・ミュートは、ブラウザの `localStorage`（キー `jigsawPuzzle.soundSettings`）に保存し、次回アクセス時に復元する。セーブデータには含めない。保存値が壊れている・範囲外の場合は初期値を使う。
- ブラウザの自動再生制限に配慮し、ユーザーの最初の操作（`pointerdown`・`pointerup`・`touchend`・`keydown`）で音声を有効にする。操作の既定動作は止めず、音声が有効になったら監視をやめる。ダブルタップ対策（`js/doubleTapGuard.js`）とは別の処理とし、そちらは変更しない。
- 音声ファイルの読み込みは待たずにゲームを始める。読み込み中・読み込み失敗の音は鳴らないだけとする。
- 音声の読み込み・再生・初期化、設定の読み込み・保存に失敗しても、ゲームの進行は止めない（ブラウザが Web Audio API に対応していない場合は音なしで遊べる）。
- iPadの消音モード（サイレントスイッチ・コントロールセンターの消音）では、Web Audio APIの音が鳴らない場合がある。実機での動作確認が必要。
- 外部の有料サービスや外部依存は増やさない。

## 7. セーブ・ロード
- セーブ方式は**手動セーブ＋画像切り替え時の保存確認**。常時自動セーブは行わない。
- 画像ごとに最大3つのセーブスロットを持つ。
- セーブ名は最大5文字。空欄の場合は「セーブ1」のように、スロット番号に応じた初期名を自動設定する。
- セーブ対象：画像の参照（画像の種類（開発者／ユーザー）＋画像ID）、パズル設定の識別情報、各ピースの位置、結合グループ、土台固定状態、表示順（z）、完成状態、保存日時、セーブ名。
- ピースの形状は画像と列数・行数から再生成できるため、セーブ対象に含めない。
- 保存先はブラウザ内のIndexedDBを基本とする。別端末・別ブラウザへの自動同期は行わない。
- ロード時は画像・設定との整合性を検証し、破損や不整合があればエラー表示して安全に処理する。
- 同じ画像で3スロットが埋まっている場合は、上書き先を選択して確認する。勝手に上書きしない。
- セーブした状態から再開後の進捗比較に使う基準は、その時点で読み込んだ状態または最後に手動保存した状態の**土台に固定されたピース数**とする。

## 8. 画像切り替え時の確認
- 現在の画像について、最後のロードまたは手動セーブ時より**土台に固定されたピース数が1個以上増えている**場合、画像切り替え時に「保存しますか？」を表示する。
- 「保存する」「保存せず切り替える」「キャンセル」の3択とする。
- 「保存する」はスロット選択と保存完了後に切り替える。保存失敗時は切り替えない。
- 「保存せず切り替える」は現在の未保存の進行を破棄して切り替える。
- 「キャンセル」は現在の画像に戻る。
- 土台に固定されたピース数が増えていない場合は保存確認なしで切り替える（ただし未保存のピース位置・結合状態は失われ得る）。
- ピース同士の結合だけが進んだ場合（土台に固定されたピース数が増えていない場合）は保存確認を表示しない。
